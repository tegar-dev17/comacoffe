# Deploy Comacoffe POS on Render (free tier)

## Architecture

| Service | Render type | Health |
| --- | --- | --- |
| `@comacoffe/api` | Web Service (Node) | `GET /ready` |
| `@comacoffe/web` | Web Service (Node) | `GET /` |
| PostgreSQL | Render Postgres (free) | linked via `DATABASE_URL` |

## 1. Connect repository (private OK)

1. [Render Dashboard](https://dashboard.render.com/) → **New** → **Blueprint**.
2. Connect GitHub and select repo `comacoffe`, branch `cursor/pos-cashier-e2e-1d81` (or your release branch).
3. Render reads [`render.yaml`](../render.yaml) at repo root.

## 2. After first deploy — set environment variables

Render assigns URLs like `https://comacoffe-api-xxxx.onrender.com` and `https://comacoffe-web-xxxx.onrender.com`.

### API service (`comacoffe-api`)

| Variable | How to set |
| --- | --- |
| `API_BASE_URL` | `https://<comacoffe-api-host>.onrender.com` (no trailing slash) |
| `FRONTEND_URL` or `CORS_ORIGINS` | `https://<comacoffe-web-host>.onrender.com` |
| `JWT_SECRET` | Auto-generated by blueprint (or set 32+ chars) |
| `MIDTRANS_SERVER_KEY` | **Secret** — Production Server Key (Dashboard only) |
| `MIDTRANS_CLIENT_KEY` | Optional (not sent to browser by this app) |
| `MIDTRANS_MERCHANT_ID` | Your merchant ID |
| `MIDTRANS_ENVIRONMENT` | `production` (from blueprint) |
| `PAYMENT_ENV` | `production` |

### Web service (`comacoffe-web`)

| Variable | When |
| --- | --- |
| `NEXT_PUBLIC_API_BASE_URL` | `https://<comacoffe-api-host>.onrender.com` — set **before** rebuild |

After changing `NEXT_PUBLIC_API_BASE_URL`, trigger **Manual Deploy** on the web service (Next.js embeds this at build time).

## 3. Database migrate & demo seed

Migrations run on each API start (`start:render` → `dist/db/migrate.js`).

One-time demo login (production-safe guard):

```bash
# Render Shell on comacoffe-api service:
ALLOW_DEMO_SEED=1 DEMO_SEED_PASSWORD='your-strong-password' npm run db:seed-demo -w @comacoffe/api
```

Login: `cashier@demo.coffee` / password you set.

## 4. Midtrans Production webhook

1. Dashboard → **Settings** → **Configuration** → **Notification URL**:
   `https://<comacoffe-api-host>.onrender.com/api/v1/webhooks/midtrans/notification`
2. Confirm via API (no secrets):
   `GET https://<api-host>/api/v1/public/info` → `suggestedMidtransNotificationUrl`, `midtransProductionReady`.

## 5. Verify

```bash
curl -s https://<api-host>/ready
curl -s https://<api-host>/api/v1/public/info
curl -s -X POST https://<api-host>/api/v1/webhooks/midtrans/notification \
  -H 'Content-Type: application/json' -d '{}' 
# Expect 401 Invalid signature (route is public, signature enforced)
```

## 6. Real QRIS test (manual, authorized by you)

1. Open `https://<web-host>/login` → kasir.
2. `/pos` → add product → **Bayar QRIS** (not mock if `midtransProductionReady: true`).
3. Scan QR with your banking app (small amount).
4. Wait for Midtrans **settlement** webhook → payment **SUCCEEDED** on `/payments/<id>`.
5. Do **not** use dev `simulate-success` in production (disabled).

## Free tier limits

- **Web services**: sleep after inactivity; first request may take 30–60s.
- **Postgres free**: **expires after 90 days** — export data or upgrade before expiry.
- **No live charges** in CI; production charges only when you initiate payment.

## Build commands (reference)

| Package | Build | Start (Render) |
| --- | --- | --- |
| API | `npm run build -w @comacoffe/api` | `npm run start:render -w @comacoffe/api` |
| Web | `npm run build -w @comacoffe/web` | `npm run start -w @comacoffe/web` |
